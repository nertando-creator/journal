# Журнал сетапов

Личный сайт для хранения скриншотов графиков: вкладки-папки, теги, статус «успех / проигрыш», комментарии.
Данные лежат в Supabase (база и приватное хранилище), сайт раздаёт Vercel. Сборщика нет: обычные HTML, CSS и JS.

## Какие файлы заливать в репозиторий GitHub

`index.html`, `styles.css`, `app.js`, `storage.js`, `config.js`, `README.md`.

`supabase_setup.sql` в репозиторий не нужен: его один раз запускают в Supabase (SQL Editor → New query → Run).

## Что не трогать

- `config.js` содержит адрес проекта и публичный ключ Supabase. При обновлении не заменяй его файлом из архива,
  если у тебя он уже заполнен.
- Ключ `service_role` нигде не используется. Не вставляй его ни в один файл.
- Не переименовывай файлы: они подключены друг к другу по именам.

## Как обновить сайт

1. Распакуй архив новой версии.
2. В репозитории на GitHub открой Add file → Upload files и перетащи файлы (кроме `config.js`, если он у тебя уже настроен).
3. Нажми Commit changes.
4. Vercel сам соберёт и опубликует новую версию, обычно за минуту. Статус виден в Vercel → Deployments.
5. Открой сайт и нажми Ctrl+F5, чтобы браузер взял новые файлы. Номер версии виден в панели «Логи».

## Как откатиться

- Быстро: Vercel → Deployments → выбери предыдущий успешный деплой → меню «⋯» → Promote to Production (или Redeploy).
- Через GitHub: открой последний коммит → Revert, и Vercel опубликует прежние файлы.

## Если что-то не работает

1. Открой «Логи» (кнопка внизу справа). Ошибки красные, переключатель «Ошибки» оставляет только их.
   Кнопка «Скопировать всё» копирует журнал целиком, его удобно прислать при вопросах.
2. Нажми Ctrl+F5, чтобы сбросить кэш страницы.
3. Нажми F12 и открой вкладку Console (ошибки скрипта) и Network (запросы, красным то, что не загрузилось).
4. Проверь `config.js`: адрес вида `https://xxxx.supabase.co` и публичный ключ, без пробелов и лишних слов.
5. Если пишет «Нет соединения», проверь интернет. Правки не теряются и досохраняются сами, когда связь вернётся.
